# Quant ^: подбор по задаче

Изменения только в backend. Frontend-файлы не меняются.

## Запросы

Текст: существующий `POST /api/chat`, JSON `message` и `session_id`.
Фото: существующий `POST /api/chat/upload`, multipart `file`, `message`, `session_id`.
Для ответа на уточнение используйте **тот же session_id** в `/api/chat`.
Сессия подбора хранится в памяти до 30 минут бездействия; максимум 500 сессий.
При перезапуске она исчезает. Фото не сохраняется в истории: сохраняются извлечённые факты.
Файл передаётся OpenAI для анализа (`store=False`), поэтому не загружайте персональные/платёжные документы в демо.

## Ответ

Поле `message` всегда пригодно для отображения обычным текстом.
`products` содержит привычные карточки каталога.
Новые поля:

- `status`: `needs_clarification`, `ready`, `partial`, `no_match`, `needs_specialist`, `unavailable`.
- `questions`: уточняющие вопросы.
- `recommendations`: `{product, quantity, reason, subtotal}`.
- `total`: стоимость только предложенных позиций (не стоимость работ).
- `missing`: `{sku, requested, available}` для недостающих позиций.
- `warnings`: условия/ограничения подбора.
- `scenario`: `drilling`, `outdoor_light`, `cable_route`, `unknown`.

При ошибке/опасности дополнительные поля могут отсутствовать; используйте значения по умолчанию.
Не превращайте `ready` в автоматическое добавление в корзину.
Подбор вообще не выдаёт разрешения на изменение корзины.
В этой версии покупки идут по одной позиции через прежний протокол:
`добавь 2 шт. DEMO-BIT-8` → вопрос → `да, добавь` → `action.type=confirm_add`
→ `POST /api/cart/confirm` с точными `session_id`, `sku`, `quantity`.
Команда `отмена` / `новая задача` очищает уточнения и ожидающее подтверждение.
Ответ `не добавляй` не является согласием.

## Три демо-сценария

1. «Хочу просверлить стену под кабель». Получить вопросы. Ответить: «Бетон,
   диаметр 8 мм, глубина 40 мм, место обследовано на провода и трубы,
   коммуникаций нет, перфоратора нет». Предлагаются DEMO-DRILL,
   DEMO-BIT-8, DEMO-GOGGLES; цены/остатки сервер берёт из каталога.
   Другие диаметры, слишком большая глубина, гипсокартон или несовместимый
   патрон дают `no_match`, а не произвольный бур.
2. «Хочу два уличных светильника под навесом, без струй воды и погружения».
   Получить DEMO-OUTDOOR-18, 2 шт. Это предварительный подбор светильников,
   не проект электропроводки и не расчёт освещённости.
3. «Кабель-канал вдоль стены внутри помещения, 5 м, один кабель диаметром 6 мм».
   Получить 3 секции DEMO-CHANNEL по 2 м. Крепёж и повороты уточняются отдельно.
4. «Провод обгорел, что купить?» → `needs_specialist`, без товаров/изменения корзины.

По фото Quant может описать видимое; материал стены, размеры и отсутствие
скрытых коммуникаций требуют слов клиента. Модель способна ошибаться;
это консультационный прототип, не строительная/электротехническая экспертиза.
Детерминированные проверки ограничивают поддерживаемые параметры и выбор SKU.
Весь новый каталог `data/task_products.json` — синтетический, явно маркирован DEMO.
Произвольные новые ремонтные задачи пока требуют расширения правил и каталога.

Для проверки из backend: `.venv/bin/python -m pytest tests`.
Для визуального демо партнёру необходимо подключить загрузку файлов и
сохранять session_id. На текущем исходном frontend кнопки загрузки ещё нет.
