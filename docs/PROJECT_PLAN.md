# План проекта HACKALEM AI

## 1. Цель MVP

За 1–2 дня собрать демонстрационный чат на сайте ekt.kz, который помогает выбрать электротехнический товар, отвечает только по данным каталога и безопасно добавляет позицию в корзину после явного подтверждения.

## 2. Результат к демо

- единое окно чата для desktop и mobile;
- каталог с артикулом, характеристиками, ценой, сертификатом и остатком;
- поиск по свободной формулировке;
- предложение аналога при нулевом остатке;
- ответы по оплате, доставке и минимальной партии;
- сценарий подтверждения: `запрос → предложение → явное “да” → изменение корзины`;
- ссылка на актуальную корзину;
- README, архитектура, инструкция запуска и чек-лист проверки.

## 3. План по этапам

### Этап 1 — Основа и данные

- создать репозиторий и структуру проекта;
- согласовать схему товара и корзины;
- загрузить синтетическую выборку каталога;
- подготовить слой, который позже можно заменить API ekt.kz.

**Готово, если:** товар ищется по артикулу и названию, а данные возвращаются в едином формате.

### Этап 2 — Чат и бизнес-правила

- реализовать классификацию запроса: товар, наличие, аналог, условия покупки, добавление в корзину;
- выводить источник ответа — карточку товара или правила покупки;
- добавить проверку остатков;
- запретить изменение корзины без явного подтверждения;
- добавить объяснение, почему предложен аналог.

**Готово, если:** все Must have проходят по API и через UI.

### Этап 3 — Интерфейс и интеграция

- собрать чат в стиле ekt.kz;
- показать карточки товаров, остаток и сертификат;
- добавить кнопку подтверждения добавления;
- показать количество товаров в корзине и ссылку на неё;
- проверить мобильную ширину и обработку ошибок.

**Готово, если:** пользователь проходит полный путь от вопроса до корзины за одну сессию.

### Этап 4 — Демо и упаковка

- записать короткий сценарий демонстрации;
- прогнать чек-лист;
- подготовить 2–3 слайда: проблема, архитектура, результат;
- назначить роли на защите: продукт, техника, демо.

## 4. Роли команды

| Роль | Ответственность |
| --- | --- |
| Product / pitch | проблема, ценность, сценарий, выступление |
| Backend / AI | каталог, поиск, чат-логика, правила безопасности |
| Frontend | чат, карточки, корзина, mobile UI |
| Data / QA | подготовка данных, тестовые вопросы, проверка критериев |

## 5. Риски и решения

| Риск | Решение для MVP |
| --- | --- |
| Нет полного API партнёра | использовать синтетические данные с той же схемой |
| Галлюцинации ассистента | отвечать только по найденным данным; неизвестное передавать менеджеру |
| Некорректное изменение корзины | отдельный endpoint подтверждения и серверная проверка остатков |
| Долгий ответ | быстрый поиск по локальному индексу; LLM подключать после базового сценария |
| Разные формулировки запросов | нормализация текста и поиск по артикулу/названию/синонимам |

## 6. Критерии успеха

- 5/5 обязательных сценариев проходят на демо;
- отсутствие товара приводит минимум к одному релевантному аналогу;
- без явного подтверждения корзина не меняется;
- количество в корзине не превышает остаток;
- ответ по товару появляется за секунды;
- интерфейс понятен без объяснения со стороны команды.
