# Единая концепция продукта

## Quant — консультант по электротехнике в чате ekt.kz

Главный продуктовый референс по механике — Kasper в Магазине Kaspi: ассистент понимает запрос, при необходимости уточняет требования, подбирает товары, сравнивает их и объясняет различия. В проекте используется только эта продуктовая логика; название, визуальный стиль и внутренние решения Kaspi не копируются.

### 1. Суть концепции

Quant — это встроенный в сайт ekt.kz чат-консультант, который переводит свободный вопрос клиента в конкретное действие:

```text
понять запрос → найти подтверждённые данные → объяснить ответ → предложить следующий шаг
```

Ассистент не является самостоятельным продавцом и не принимает решения за клиента. Он помогает с выбором, но любое изменение корзины происходит только после явного подтверждения пользователя.

### 2. Пользовательская проблема

Покупателю электротехнической продукции часто нужно одновременно проверить:

- подходит ли товар по техническим параметрам;
- есть ли он в наличии;
- сколько он стоит;
- есть ли сертификат;
- что выбрать, если позиции нет;
- как купить и доставить товар.

Если на каждый вопрос нужно звонить или ждать ответа менеджера, клиент откладывает покупку. Менеджер при этом тратит время на повторяющиеся консультации.

### 3. Решение

В чате пользователь спрашивает обычными словами. Система:

1. определяет тип запроса;
2. ищет совпадение в каталоге;
3. возвращает только подтверждённые поля товара;
4. при отсутствии позиции подбирает аналог;
5. объясняет, чем аналог релевантен;
6. предлагает добавить товар, но ждёт явного «да»;
7. проверяет остаток на сервере;
8. возвращает ссылку на актуальную корзину.

Подбор строится не вокруг одного совпадения по ключевому слову, а вокруг задачи клиента. Например, запрос «нужен кабель для прокладки в помещении, медный, 3x2.5, с низким дымо- и газовыделением» должен превратиться в набор фильтров, затем в 2–3 варианта и понятное сравнение.

### 4. Главный принцип доверия

**Ассистент не должен выдумывать данные.**

Если в каталоге нет цены, сертификата, остатка или характеристики, пользователь видит честное сообщение: «Нет подтверждённых данных, уточните у менеджера». Это важнее, чем красивый, но недостоверный ответ.

### 5. Объём MVP

В MVP входит один веб-чат с четырьмя типами запросов:

| Тип запроса | Результат |
| --- | --- |
| Информация о товаре | цена, наличие, характеристики, сертификат |
| Поиск аналога | доступная позиция и причина рекомендации |
| Условия покупки | оплата, доставка, минимальная партия |
| Добавление в корзину | подтверждение, проверка остатка, ссылка |

Файлы и изображения, казахский язык, история авторизованного пользователя и менеджерская эскалация остаются следующим этапом, но архитектура не должна мешать их подключить.

### 5.1 Каталог как база ekt.kz

Агент работает поверх существующей логики ekt.kz, а не поверх абстрактного магазина. В первую очередь поддерживаются категории:

- кабель и провод;
- светильники и лампы;
- низковольтная аппаратура;
- кабеленесущие системы;
- изделия для монтажа и инструмент;
- шкафы и щиты;
- розетки, выключатели и коробки;
- автоматизация;
- видеонаблюдение, СКУД и сигнализация;
- инструмент и КИП.

Важный контекст ekt.kz: город/регион влияет на остаток, склад, доступность самовывоза и доставку. Поэтому `warehouse`, `city`, `stock` и правила доставки должны стать частью каталожного контекста, а не статичным текстом в ответе.

### 5.2 Механика сравнения

Если найдено несколько вариантов, ассистент показывает сравнение минимум по трём группам:

| Группа | Примеры |
| --- | --- |
| Техническая совместимость | сечение, ток, напряжение, количество полюсов, IP |
| Экономика | цена, доступный остаток, длина/комплектация |
| Практический выбор | где использовать, ключевой плюс, ограничение |

Рекомендация должна содержать формулу: **«подходит потому что …; отличается от варианта B тем, что …»**. Если параметр не подтверждён в каталоге, он не участвует в сравнении.

### 6. Точный UX-сценарий

#### Состояние A — первый вход

На экране есть короткое объяснение: «Спросите про товар, наличие, характеристики, сертификаты или аналоги». Рядом — быстрые примеры запросов.

#### Состояние B — поиск

Пользователь пишет вопрос. Frontend показывает его сообщение и loading-состояние. Повторная отправка блокируется.

#### Состояние C — результат

Ответ состоит из краткого текста и, если найден товар, карточки с ключевыми данными. Длинные технические характеристики не должны перегружать первое сообщение — их можно показывать структурированным списком.

Если запрос широкий, ассистент сначала задаёт 1–3 уточняющих вопроса: назначение, ключевой параметр, бюджет/количество и город поставки. После этого показывает сравнение нескольких вариантов, а не случайный первый результат.

#### Состояние D — товар отсутствует

Сначала показывается честное сообщение о нулевом остатке, затем доступный аналог. В объяснении указываются совпадающие параметры, например категория и сечение.

#### Состояние E — подтверждение

Перед изменением корзины обязательно показать:

- название товара;
- количество;
- текущий остаток;
- итоговое действие.

Текст должен быть однозначным: «Добавить 2 шт. в корзину?». Нажатие на карточку или рекомендацию не считается подтверждением.

#### Состояние F — корзина

После подтверждения пользователь видит обновлённое количество, сумму и ссылку на корзину/оформление. Платёжные данные в ассистенте не запрашиваются.

### 7. Требования к данным

Источник для MVP — синтетическая или обезличенная выборка каталога с полями:

```json
{
  "sku": "EK-VA4729-C16",
  "name": "Автоматический выключатель ВА47-29 2P C16",
  "category": "Автоматические выключатели",
  "characteristics": {},
  "certificate": {"name": "...", "url": "..."},
  "price": 1850,
  "stock": 42,
  "warehouse": "Алматы"
}
```

В продуктивной версии источник заменяется API или выгрузкой ekt.kz, но внешний контракт для frontend сохраняется.

### 8. Безопасность и ограничения

#### Защищённые действия

- чат может подготовить предложение, но не меняет корзину;
- подтверждение хранится на сервере в контексте сессии;
- endpoint подтверждения проверяет сессию, SKU, количество и остаток;
- повторное использование подтверждения запрещается;
- количество ограничивается доступным остатком;
- сервер не доверяет только данным, пришедшим из браузера.

#### Конфиденциальность

- не запрашивать платёжные реквизиты;
- не хранить лишние персональные данные;
- не выводить внутренние ошибки и ключи API;
- не передавать в LLM данные, которые не нужны для ответа;
- при подключении истории определить срок хранения и способ удаления.

### 9. Нефункциональные требования

- ответ в обычном сценарии — за единицы секунд;
- интерфейс работает на desktop и mobile;
- текст читается на небольшом экране;
- ошибки сети отображаются понятно;
- система остаётся работоспособной при пустом результате поиска;
- логи не содержат платёжные данные;
- архитектура допускает замену JSON на API партнёра.

### 10. Что показываем на защите

Одна история без переключения между разными продуктами:

1. найти существующий автомат;
2. показать характеристики и сертификат;
3. запросить отсутствующий кабель;
4. получить аналог с объяснением;
5. попросить добавить товар;
6. показать, что без «да» корзина не изменилась;
7. подтвердить добавление;
8. открыть актуальную корзину.

### 11. Формулировка ценности для презентации

> «Quant сокращает путь от вопроса до корзины: клиент получает точные данные по товару, видит релевантную замену при отсутствии позиции и сохраняет полный контроль над покупкой. Менеджер подключается там, где действительно нужна экспертная консультация.»

### 12. Граница концепции

Это не универсальный чат-бот и не автономный продавец. Это специализированный ассистент каталога и корзины, который отвечает в пределах подтверждённых данных ekt.kz и аккуратно передаёт сложные случаи человеку.
