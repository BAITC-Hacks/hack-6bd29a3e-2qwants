# Запуск первой интеграции Quant + backend

## Объединённая версия

Инструкции ниже описывают первую интеграцию партнёра. После объединения:

- Запуск из `backend`: `.venv/bin/python -m uvicorn app.main:app --reload --port 8001`.
- Открыть `http://127.0.0.1:8001/static/visual-demo.html`.
- `demo.js` получает все 10 демо-позиций через `GET /api/products` и использует отдельную сессию на каждый чат. `api-bridge.js` и статический снимок каталога не подключаются к странице.
- Фото и 3D работают через `product-media.js`; выбор количества из просмотра открывает карточку в чате и сохраняет серверное подтверждение корзины.
- Для проверки интерфейса: `node frontend/integration-browser-check.cjs` с установленным Playwright. Для установленного Chrome задайте `QUANT_BROWSER_CHANNEL=chrome`. Тест создаёт отдельную демо-сессию, проверяет три 3D-модели и добавляет два товара в её корзину.
- Серверные тесты: из `backend` выполнить `.venv/bin/python -m pytest -q`.
- `api-bridge-smoke.js` относится к прежнему, отключённому подключению.

## Историческая инструкция

Интеграция подготовлена в рабочей ветке `integration/quant` без изменения backend партнёра. Исходная папка `new-chat` с незакоммиченными изменениями сохранена отдельно.

## Запуск

Из папки `quant-integrated/backend`:

```bash
.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8010
```

Открыть `http://127.0.0.1:8010/`. Порт 8000 был занят другим процессом. Виртуальное окружение установлено в `backend/.venv` и не входит в Git.

## Что соединено

- Чат отправляет текст на `POST /api/chat` и показывает полученный ответ.
- После явного подтверждения выбранного товара frontend проходит серверные шаги `POST /api/chat` → подтверждение → `POST /api/cart/confirm`, затем считывает `GET /api/cart/{session_id}`.
- Загрузка допустимого файла отправляется на `POST /api/chat/upload` без сохранения содержимого во frontend. Без `OPENAI_API_KEY` backend честно сообщает, что анализ недоступен.
- Сертификаты открываются через `/api/certificates/...`.
- Каталог на витрине берётся из `frontend/backend-catalog.json` — это точная копия синтетического `backend/data/products.json` на момент подготовки интеграции. В backend нет `GET /api/products`, поэтому обновление каталога пока требует новой копии файла. Это **не живые остатки**.

## Найденные ограничения для следующего этапа

1. Backend отвечает в основном по-русски; полноценный KZ-ответ и перевод карточек ещё не интегрированы.
2. В backend нет endpoint списка товаров. Для актуальных остатков и цен потребуется согласованный `GET /api/products` или другой каталог API; статический снимок нужно убрать.
3. `/cart?session_id=...` возвращает демо-страницу, а не реальное оформление заказа ekt.kz. Кнопка оформления не выполняет покупку.
4. Запрос по названию отсутствующего кабеля иногда возвращает сразу доступную бухту вместо сообщения об отсутствии исходной позиции. По точному артикулу аналог работает.
5. Ответы по оплате/доставке пока текст демо-версии backend, не подтверждённые условия партнёра.
6. `OPENAI_API_KEY` не настроен: обработка вложений на API отвечает «AI-анализ недоступен»; сам файл при этом принимается.
7. История чатов хранится во вкладке frontend, а backend хранит корзины и pending-подтверждения только в памяти процесса. После перезапуска сервера корзина сбросится.

## Проверки

Из корня рабочей копии:

```bash
cd backend && .venv/bin/python -m pytest tests -q
```

Frontend smoke-тесты на macOS:

```bash
/System/Library/Frameworks/JavaScriptCore.framework/Versions/A/Helpers/jsc frontend/demo-smoke.js
/System/Library/Frameworks/JavaScriptCore.framework/Versions/A/Helpers/jsc frontend/api-bridge-smoke.js
```
