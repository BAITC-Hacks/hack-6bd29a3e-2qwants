# Quant: подключение frontend к backend

`frontend/visual-demo.html` подключён к локальному FastAPI backend. Каталог загружается через `GET /api/products`, чат — через `POST /api/chat`, вложение — через `POST /api/chat/upload`, корзина — через серверные маршруты. Данные остаются синтетическими и не являются данными реального ekt.kz.

## Ответственность

| Frontend | Backend и партнёр ekt.kz |
| --- | --- |
| Интерфейс Quant, RU/KZ, карусели, история в текущей вкладке, отображение карточек и состояния подтверждения | Каталог, актуальные цены и остатки по складам, сертификаты, официальные условия покупки |
| Показывает выбранный товар и количество; отправляет действие лишь после явного клика/ответа клиента | Проверяет сессию и подтверждение, повторно проверяет остаток, изменяет реальную корзину и возвращает её актуальное состояние |
| Отображает ссылку на корзину из ответа API | Предоставляет работающий URL корзины/оформления заказа и защищает его от чужих сессий |

## Выполненное подключение

1. Каталог и карточки получают серверные SKU, цену и остаток.
2. Сообщения и ответы на уточнения используют `session_id` выбранного чата.
3. Фото/документы отправляются по одному файлу до 10 МБ.
4. Явное подтверждение вызывает серверный `POST /api/cart/confirm`.
5. Корзина обновляется из ответа backend и из `GET /api/cart/{session_id}`.

Локальные функции старого визуального демо сохранены для компонентов сравнения, но основной `send()` работает через API. Настоящий API ekt.kz и настоящая checkout-страница ещё не подключены.

## Несовпадения текущих схем

- В UI у товара `warehouses: {город: количество}`; в тестовом backend сейчас `stock` и один `warehouse`. Нужны согласованные остатки по складам и единый статус наличия.
- Артикулы части демо-товаров не совпадают с `backend/data/products.json`. При интеграции нужен единый каталог партнёра; нельзя сопоставлять товары только по похожему названию.
- Тестовый `checkout_url` backend указывает на `/cart?session_id=...`, но реальная страница корзины/оформления пока не подключена. Нельзя выдавать этот URL как работающий checkout.
- RU/KZ, анализ вложений и история авторизованного клиента отсутствуют в текущем API; визуальные возможности frontend не означают готовность этих серверных функций.
- Ответы об оплате, доставке и минимальной партии должны поступать из подтверждённого источника партнёра, а не из текста демо.

## Проверка перед объединением

1. По артикулу возвращаются реальные характеристики, цена, остатки по складам и только существующий сертификат.
2. При нулевом остатке аналог содержит проверяемое объяснение совместимости; иной номинал автомата не называется прямой заменой.
3. Без явного подтверждения корзина на сервере не меняется. Повторный клик старой кнопки не подтверждает новый товар.
4. Количество проверяется сервером повторно в момент добавления; превышение остатка возвращает понятную ошибку.
5. Ссылка после подтверждения открывает актуальную корзину того же клиента. Платёжные данные в чат не принимаются и не сохраняются.

Пока подключение не началось, backend-файлы не изменяются ради визуального демо.
